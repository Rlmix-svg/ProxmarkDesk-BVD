# ProxmarkDesk BVD 1.9 — второй архитектурный перенос

Версия 1.9 продолжает безопасный перенос 1.8 и закрывает проблемы, найденные при испытании первого архитектурного шага.

## 1. Command Session Manager теперь действительно владеет потоком

В 1.8 `submit()` мог вытеснить уже выполняющуюся команду и потерять её `PMDESK_END_*` marker. Это создавало риск смешивания stdout двух операций.

В 1.9:

- новая команда не вытесняет текущую;
- одновременно потоком клиента владеет только одна операция;
- вторая команда получает отказ до подтверждённого завершения первой;
- результат команды и синхронизация потока разделены: timeout может завершить ожидание UI, но marker остаётся владельцем потока;
- после timeout новая команда блокируется до прихода старого marker;
- `Stop` отправляет `hw break`, но не освобождает очередь до подтверждённой синхронизации;
- поздний marker восстанавливает возможность выполнения следующей команды без reconnect.

Обычная ошибка команды, timeout и Stop не меняют физическое состояние USB.

## 2. Устранён stale capability после нового поиска

Перед `auto`, `hf search` и `lf search` немедленно очищаются:

- текущая live-карточка;
- `tagCached`;
- `TagState`;
- `currentCapability`.

UI сразу получает новый revision со статусом поиска. Старый UID/capability не может молча участвовать в новой RF-операции.

## 3. Второй перенос Action Registry

Через stable Action ID дополнительно переведены прикладные действия:

- `hw tune`, `hw version`, `hw status`;
- Lua environment check и список Lua;
- LF read и декодирование текущего LF-буфера;
- `data save` для управляемых приложением сохранений;
- полный Classic dump с импортированным `classic-keys.bin`;
- основные start/view действия Sniff;
- сохранение текущей ISO14443-A трассы BVD.

Ручная PM3 Console намеренно остаётся прямым вводом произвольной команды: это профессиональный escape hatch, а не обход архитектуры прикладными кнопками.

## 4. Пятиэкранный shell

Основная навигация теперь соответствует утверждённой концепции:

1. Карта
2. Ключи
3. Операция
4. Библиотека
5. Инструменты

Старые рабочие страницы не удалены. Они доступны из «Инструменты» и используются как внутренние маршруты во время постепенной миграции.

«Ключи» не использует исторический UID как live-контекст. Для cached-карточки предлагается повторно обнаружить карту.

## 5. Stop

Кнопки Stop в Sniff и Emulation переведены на общий `stopCommand()` / `CommandSessionManager.cancel()`. Прямой UI-вызов `hw break` больше не считается нормальным способом остановки прикладной операции.

## 6. Визуальный слой

Основной shell переведён на тёмную базовую палитру и пять разделов. Полная визуальная доводка каждого вложенного legacy-экрана остаётся отдельной UI-задачей; функциональные экраны сохранены, чтобы не потерять рабочие возможности.

## 7. Что остаётся после 1.9

- SavedCard и полноценная модель связанной истории артефактов;
- универсальный Dump Viewer через Protocol Adapter;
- полная capability-based эмуляция по firmware/subtype;
- полный перенос динамических Sniff/Lua/каталожных сценариев в типизированные adapters;
- расширение LF/T55xx/Magic Card UI;
- ручные испытания на физическом телефоне: success → bad params → next command; no tag; Stop; physical detach.
