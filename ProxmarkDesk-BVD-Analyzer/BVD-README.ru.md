# ProxmarkDesk BVD Analyzer 1.2

Android 11–16, ARM64. Встроенный Iceman v4.21611; Termux не требуется. USB OTG и root используются существующей службой ProxmarkDesk.

## Установка

Установите `ProxmarkDesk-BVD-1.2-arm64.apk`. Пакет и сертификат прежние: APK обновляет ProxmarkDesk 0.7, сохраняя его приватную библиотеку. Перед установкой рекомендуется экспортировать важные дампы. Если установленная копия подписана другим сертификатом, Android отклонит обновление; не удаляйте приложение до экспорта данных.

## BVD Analyzer

Прокрутите верхние вкладки вправо до **BVD Analyzer**.

1. Сохраните дамп собственной NTAG/Ultralight через вкладку **Чтение** либо импортируйте BIN, EML или JSON.
2. Нажмите **Создать профиль из сохранённого дампа**. Задайте имя, результат вашей проверки на считывателе и при необходимости известные PWD/PACK.
3. Профиль сохраняет UID, доступные страницы по 4 байта, источник, время и подпись IC, если она присутствует в поддерживаемом формате дампа. BIN MFU с заголовком 56 байт распознаётся по UID/BCC в памяти страниц.
4. **Сравнить сохранённые профили** показывает различающиеся страницы всех профилей. Данные отсутствующих страниц не заполняются нулями.
5. Нажатие на профиль открывает отчёт, экспорт JSON и удаление с подтверждением.
6. Импортируйте трассу A: бинарную `.trace` Iceman или текст `hf 14a list`. Затем импортируйте B для сравнения. Вывод показывает первое различие и соседние кадры. Сравнение позиционное: повторы и пропуски могут сдвинуть последующие кадры.
7. **Экспорт отчёта** сохраняет текст через системный файловый диалог. HF-захват с подключённого Proxmark3 можно сохранить кнопкой в разделе BVD и затем импортировать из экспортированного файла.

Результат «Рабочая / Не открывает» указывается пользователем. PWD/PACK, UID или определённые значения страниц сами по себе не доказывают право доступа и не позволяют установить причину отказа домофона. Приложение не содержит предположения об «активной карте» по FE/FF и не привязано к UID из отчёта.

## Сборка и проверка

Java-интерфейс собран с Android API 36 и D8; native-клиент повторно использован из ранее собранной версии 0.7 без изменений. Подпись APK и выравнивание проверяются инструментами Android Build Tools. `tests/BvdTests.java` проверяет извлечение UID, сохранение частичных страниц, JSON, сравнение профилей, трасс и валидацию PWD.

Проверка установки и новых экранов на физическом Android, RF-чтение и работа с домофоном в этой сессии не выполнялись.

`build.py` позволяет собрать интерфейс и native-клиент из исходного дерева Iceman; параметры перечислены в `build.py --help`. Исходники native-клиента предоставлены в исходном пакете пользователя. Локальный ключ подписи не включается в архив исходников.
