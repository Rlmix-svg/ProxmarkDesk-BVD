# ProxmarkDesk BVD Android 1.6

Версия 1.6: новая вкладка чтения с подбором команд/Lua по семейству; общий каталог Lua/Python/команд, поиск и избранное; восстановление ресурсов Lua при обновлении. Диагностика: «Команды → Lua: диагностика и библиотеки». Сохранённые последовательности команд перенесены туда же из отдельной вкладки. Проверены загрузка 22 библиотек и синтаксис Lua в офлайн-клиенте Windows; работа этой сборки с метками на Android ещё требует проверки.

Самостоятельное приложение для собственного Proxmark3 Easy. Клиент Iceman v4.23346 и его ресурсы включены в APK. Termux и отдельная установка Python не нужны. CPython 3.14.7 включён в APK; запуск скриптов находится во вкладке Python. Нативный SWIG Python в клиенте Iceman не включён. Лицензии Python и его библиотек доступны на вкладке Python.

## Ранее добавлено в 0.4: автоматическая информация о метке

Нажмите **Чтение → Автопоиск HF / LF**, **Поиск HF** или **Поиск LF**. Держите одну метку на антенне до завершения сбора сведений. Приложение остаётся на вкладке «Чтение», заполняет карточку метки и выбирает семейство; для распознанной Classic также подставляет размер.

После успешного поиска автоматически выполняется подходящая команда информации. Для Ultralight/NTAG это `hf mfu info --noauth`; для Classic — публичная информация `hf 14a info`. Поддержаны дополнительные команды информации для ISO 15693, DESFire, ISO 14443-B, FeliCa, iCLASS, LEGIC и Topaz, когда поиск предоставил идентификатор. Для LF EM410x/HID сведения берутся из результата поиска. Другие распознанные протоколы сохраняют доступный вывод поиска; универсальной команды получения всех сведений для любого типа метки нет.

В карточке показаны UID/ID, тип и доступные сведения о памяти, производителе, BCC, блокировках и подписи. **Все сведения о найденной метке** открывает полный результат, включая счётчики и конфигурацию, если их вернул клиент. **Экспорт карточки метки** сохраняет текстовый отчёт. Весь поиск и дополнительные команды записываются одной операцией в журнал; отчёт также сохраняется в приватной библиотеке `cards`.

Те же автоматические действия работают для отдельных команд `auto`, `hf search`, `lf search` в консоли. Поиск в сохранённом буфере, справка и произвольные составные команды не запускают дополнительное RF-чтение. Это поиск по нажатию, а не непрерывное сканирование.

Если UID изменился, дополнительный результат не присоединяется к прежней метке. Неудачный новый поиск сбрасывает предыдущую карточку. Семейство и объём из эвристики Iceman остаются предварительными, если сам клиент указал возможные типы. Закрытая память требует известного ключа/пароля; дамп читается отдельно кнопкой сохранения.

В native-клиент добавлен параметр `hf mfu info --noauth`: он пропускает встроенные автоматические проверки стандартных 3DES/AES-ключей и EV1/NTAG-паролей. Обычная команда без этого параметра сохраняет поведение Iceman. Автоматическое чтение не запускает подбор пароля. Известные ключи по-прежнему вводятся пользователем для соответствующих операций чтения.

Сборка и 28 регрессионных проверок определения меток/сбора информации пройдены. Проверка реального автоматического чтения на телефоне ещё требуется. Подпись обновления сохранена: устанавливайте поверх предыдущей версии.

## Обновление 0.3: исправление запуска через root

Исправлена ошибка `env: exec --incognito: No such file or directory`. Теперь HOME задаётся встроенной командой shell `export`, затем Iceman запускается напрямую через `exec`. Это исключает разбор пути к клиенту как переменной окружения утилитой `env`, если путь установки содержит `=`. В коде [Toybox env](https://raw.githubusercontent.com/landley/toybox/master/toys/posix/env.c) аргументы со знаком `=` обрабатываются как присваивания; точный путь установки на телефоне в предоставленном журнале не указан.

Установите 0.3 поверх предыдущей версии. Нажмите **Остановить сеанс → Подключить по USB**, порт `/dev/ttyACM0`, root включён. В предыдущем отчёте уже подтверждены устройство `9AC4:4B8F`, драйвер `cdc_acm`, режим host и uid=0. Ошибка `env` возникала до запуска Iceman и до открытия порта. Если появится другая ошибка, экспортируйте консоль.

Проверены 13 регрессионных сценариев построения и выполнения команды shell с тестовым клиентом, включая пути с `=`, пробелами, кавычками и shell-символами. Это локальные проверки запуска, а не проверка root/USB на Android. Native-клиент не изменён.

## Обновление 0.2: диагностика подключения

Установите APK поверх 0.1: идентификатор приложения и ключ подписи сохранены. Удалять предыдущую версию не нужно; приватная библиотека и настройки сохраняются при обычном обновлении.

Кнопка **Найти USB / tty-порты** теперь проверяет код завершения `su`, фактический UID, возможность перечислить `/dev`, USB-устройства и tty-интерфейсы в sysfs, а также доступные сведения о USB-роли. Ошибки root, неполный ответ и тайм-аут не выдаются за отсутствие устройства. Несколько tty-портов можно выбрать из списка. Полный отчёт доступен кнопкой **Экспорт диагностики USB**; он также доступен из диалога результатов.

Пустую команду больше нельзя отправить. Штатное закрытие сеанса не выводит ложную ошибку `read interrupted by close() on another thread`. Кнопки USB и офлайн переименованы: офлайн запускает клиент без подключения к меткам.

Если USB и tty не найдены, проверьте включение OTG в настройках телефона, подключение кабеля с передачей данных и питание Proxmark3. Переподключите устройство и повторите поиск. Если оно снова не найдено, экспортируйте отчёт. Пустой список сам по себе не позволяет установить, виноваты ли кабель, режим USB, драйвер или ограничения доступа. Диагностика не меняет USB-роли, права файлов или SELinux.

## Установка

1. Перенесите `ProxmarkDesk-Android-arm64.apk` на телефон и установите через файловый менеджер. При необходимости разрешите этому файловому менеджеру установку приложений.
2. Подключите Proxmark3 через OTG. Закройте ранее запущенный клиент, занимающий устройство.
3. Откройте вкладку **Устройство → Найти USB / tty-порты**. Для вашего устройства ожидается `/dev/ttyACM0`.
4. Оставьте **Использовать root**, нажмите **Подключить по USB** и разрешите доступ в менеджере root. Если офлайн-сеанс уже открыт, сначала нажмите **Остановить сеанс**.
5. Во вкладке **Чтение** нажмите **Автопоиск HF / LF**. Для показанной вами метки выберите **Ultralight / NTAG → Информация / Сохранить дамп**.

Требования: Android 11–16, процессор ARM64, USB OTG, root для последовательного USB-порта. Сборка нацелена на Android 16 / API 36; встроенный ELF имеет выравнивание 16 КиБ. Поддержка конкретной политики root/SELinux и USB-драйвера проверяется на телефоне. Наличие root само по себе не гарантирует разрешение всех операций.

## Возможности

- Автопоиск HF/LF, информация о метке, выбор семейства, чтение блока, NDEF и дампы для поддерживаемых формой семейств.
- Консоль встроенного Iceman и поиск в его каталоге команд. Каталог загрузите кнопкой **Получить каталог**.
- Sniff для ISO 14443-A/B, ISO 15693, FeliCa, iCLASS, Topaz, LF. Команду захвата, удерживающую консоль, завершайте физической кнопкой Proxmark3. Затем покажите и сохраните захват до отключения сеанса.
- Импорт/экспорт BIN, JSON, EML и трасс через системный выбор файлов. HEX, сравнение, SHA-256, UID/BCC Type 2, базовый NDEF, проверка инверсий ACL Classic, просмотр сигнала PM3.
- Постоянный сеанс в фоновой службе и журнал каждой операции. Неполный дамп отмечается отдельно. Файлы сохраняются в приватной библиотеке приложения; экспортируйте нужные перед удалением приложения.

Для JSON MFU данные извлекаются из `blocks`. Для бинарного MFU с заголовком Iceman выберите **BIN MFU: заголовок 56 байт**. Не отбрасывайте 56 байт у обычного BIN с чистой памятью. Дамп 34/41 страниц остаётся частичным; приложение не восстанавливает непрочитанные страницы.

Python, Qt, native Bluetooth и desktop readline в эту сборку не входят. Lua включён; Lua-скрипты, вызывающие внешние desktop-утилиты, могут требовать адаптации. Операции, требующие других аппаратных модулей Proxmark3, остаются ограничены возможностями Easy. Полного соответствия настольному клиенту нет.

Кнопка **Стоп** завершает клиентский сеанс. Если устройство продолжает RF-операцию, нажмите его физическую кнопку. Отключение интерфейса не всегда прекращает автономную операцию прошивки.

## Проверка сборки

Это тестовая сборка. Скриншоты пользователя подтвердили установку 0.1, запуск встроенного клиента Android/aarch64 в офлайне и уведомление о выдаче root. USB-связь не установлена; её причина пока неизвестна. Для 0.2 проверены компиляция Java, подпись и упаковка APK, а также 21 проверка диагностики и ввода команд. Native-клиент и анализатор не изменены. Подробности — в `VALIDATION.txt`. Новую версию ещё нужно проверить на телефоне. Прошивка Proxmark3 при подключении не обновляется.

При ошибке подключения экспортируйте консоль и пришлите журнал. Для первичной диагностики сначала можно открыть **Клиент офлайн**, затем выполнить `hw version` и получить каталог команд.

## Исходники и сборка

Интерфейс: GPL-3.0-or-later. Iceman и зависимости сохраняют собственные лицензии, прилагаемые в исходном дереве и `assets/licenses.zip`. Полный исходный код встроенного клиента с изменениями CMake находится в `ProxmarkDesk-Android-native-source.zip` рядом с этим проектом.

Сборка не использует Gradle и внешние Maven-зависимости. Нужны Python 3 на компьютере, JDK 17, Android SDK Platform 36, Build Tools 36.0.0, NDK r28c, CMake/Ninja. `build.py --help` перечисляет пути к инструментам. `--native-source` должен указывать на распакованный каталог `proxmark3-4.21611`. Сначала собирается native-клиент, затем Java/D8, APK выравнивается и подписывается локальным ключом разработки. Храните созданный keystore, чтобы подписывать обновления тем же ключом.

Источники: [Iceman v4.23346](https://github.com/RfidResearchGroup/proxmark3/tree/v4.23346), [Android NDK](https://developer.android.com/ndk/downloads), [поддержка страниц 16 КиБ](https://developer.android.com/guide/practices/page-sizes).
