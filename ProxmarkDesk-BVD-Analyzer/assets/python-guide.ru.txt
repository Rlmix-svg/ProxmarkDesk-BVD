# ProxmarkDesk BVD 1.5 — Python без Termux

В APK добавлена отдельная среда CPython 3.14.7 для Android ARM64. Она работает в процессе приложения без root. Существующий клиент Iceman продолжает использовать выбранный способ подключения к Proxmark3. Пакет приложения и сертификат обновления сохранены.

## Первое использование

1. Откройте вкладку **Python** и нажмите **Проверить встроенный Python**. Устройство не требуется. Проверка печатает версии Python, OpenSSL, SQLite и результат работы основных модулей.
2. Для полезного примера без устройства запустите `dump_inventory.py`: он составляет опись сохранённых дампов с размерами и SHA-256.
3. Для проверки связи откройте сеанс Iceman и запустите `device_report.py`. Он выполняет `hw version` через уже открытый клиент. В офлайн-сеансе отчёт описывает клиент, а не физическое устройство.
4. Полный вывод, ошибки и прерванные выполнения доступны в **Журнале**. Отчёты сохраняются в `reports/` библиотеки текущего профиля; их можно экспортировать кнопкой на вкладке Python.

## Что включено

- Отдельный управляемый процесс Python, выбор предельного времени 1–86400 секунд, остановка без автоматического повтора сценария.
- Стандартная библиотека, включая JSON, CSV, SQLite, hashlib, SSL, ctypes, ZIP и основные модули сжатия. Проверка SSL проверяет наличие модуля, а не доступ к интернету или доверие сертификатам сайтов.
- Аргументы без запуска оболочки; аргументы с пробелами заключаются в одинарные или двойные кавычки. Обратные слэши сохраняются буквально.
- `input()` отображается в окне приложения; ожидание ответа ограничено 600 секундами.
- Импорт пользовательских `.py` размером до 1 МиБ, просмотр исходного кода, поиск в списке. Импорт сам по себе ничего не запускает. Скрипты хранятся в `scripts/python/` и попадают в резервную копию библиотеки.
- Запись вывода по мере поступления. При ошибке сохранения выполнение прекращается; по завершении запись синхронизируется с накопителем.
- Адаптер `pm3` для команд существующего клиента. Локальный канал связи принимает запросы только с одноразовым секретом текущего запуска; он не слушает внешние сетевые интерфейсы.

Встроенные скрипты: `python_selftest.py`, `device_report.py`, `dump_inventory.py`, `pm3_eml2mfd.py`, `pm3_mfd2eml.py`, `pm3_nfc2eml.py`, `findbits.py`, `parity.py`, `xorcheck.py`, `pm3_help2json.py`, `pm3_help2list.py`. Последний адаптирован для перечисления файлов без Git. Все скрипты запускаются только по выбору пользователя.

## Пример собственного скрипта

```python
from pm3 import pm3, library_path

p = pm3()
status = p.console("hw version", timeout=30)
print(p.grabbed_output)
print("Библиотека:", library_path())
print("Код результата:", status)
```

`console()` поддерживает параметры `capture`, `quiet`, `timeout`. Возвращает 0 при завершении без распознанных ошибок/предупреждений и 1, если вывод требует проверки. Это оценка по тексту клиента, не точный набор кодов нативного SWIG. Ошибки соединения вызывают исключение Python. Чтение из устройства, запись и прочие команды по-прежнему зависят от возможностей оборудования, прошивки и метки.

Для файловых скриптов рабочая папка — библиотека выбранного профиля. Примеры аргументов показаны в форме запуска. Конвертеры могут перезаписать указанное имя выходного файла; используйте новое имя для сохранения исходного дампа.

## Границы совместимости

Это самостоятельная среда с адаптером, а не включение нативного SWIG Python в Iceman. Запуск выполняется на вкладке Python; `script run …py` внутри нативной консоли Iceman не становится доступным. Адаптер поддерживает `pm3.pm3()`, `console()`, `grabbed_output`, `name`; произвольный `_pm3` API не реализован.

Pip, NumPy, pyamiibo и другие сторонние пакеты не включены. Скрипты, требующие их, внешних desktop-программ, отдельного доступа к USB или особенностей SWIG, нуждаются в адаптации. Наличие Python не исправляет автоматически зависимости Lua-скриптов. Пользовательские скрипты имеют доступ приложения к его файлам и сети; это не изолированная среда для недоверенного кода.

Остановка Python закрывает его процесс. Если в этот момент выполняется команда Iceman, приложение также закрывает клиентский сеанс, чтобы следующая операция не получила незавершённый ответ. При оставшемся активном RF-режиме используйте кнопку самого Proxmark3. Запись, уже выполненная устройством, остановкой не отменяется.

## Сборка и происхождение

Официальный пакет: https://www.python.org/ftp/python/3.14.7/python-3.14.7-aarch64-linux-android.tar.gz

SHA-256 скачанного пакета: `6d50cc3aa66e414a439594089bcdfb5f1264358155c70c1f00471c24cfb477fb`.

Документация встраивания: https://docs.python.org/3.14/using/android.html

`prepare-python.py` получает распакованный `prefix`, путь `--ndk-bin` и `--iceman`, компилирует `native/python-launcher.c`, упаковывает стандартную библиотеку и скрипты. `build.py` включает `python-native/arm64-v8a/*.so`; для повторного приготовления среды есть аргумент `--python-prefix`. Пример на Windows:

```text
python prepare-python.py --prefix PATH/TO/prefix --ndk-bin PATH/TO/ndk/toolchains/llvm/prebuilt/windows-x86_64/bin --iceman PATH/TO/proxmark3
```

Тексты лицензий доступны в приложении и `assets/python-licenses/`. CPython распространяется по PSF License, OpenSSL — Apache-2.0, libffi — MIT, libbzip2 — по собственной лицензии, liblzma и SQLite — public domain, zstd — BSD. Исходники нативного Iceman и его изменения остаются из ранее поставленного комплекта; архив исходников приложения не заменяет полный исходный пакет Iceman.

Проверки: компиляция Android, подпись и выравнивание APK; зависимости и выравнивание 16 КиБ всех 59 библиотек Python; тесты управления процессом, UTF-8, ошибок, тайм-аута, отмены, локального протокола, ввода и конвертеров на компьютере. Это не заменяет запуск ARM64-интерпретатора на телефоне. Аппаратная проверка этого обновления на Android/Proxmark3 ещё не выполнена.
